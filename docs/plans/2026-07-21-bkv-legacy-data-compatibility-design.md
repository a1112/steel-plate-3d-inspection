# BKV 旧系统数据兼容与离线回放设计

## 背景

旧系统数据来自以下归档：

- `database.zip`：MySQL `ncdtube` 数据库转储；包含 `allexcel`、`camera`、`checkrecord`、`defect`、`defectclass`、`diameter` 等表。
- `image_copy.part1.rar`、`image_copy.part2.rar`：六路旧相机的 2D、3D 和辅助数据。

只迁移与图片归档对应的 `SeqNo 1893700-1893710`，共 11 支钢管。数据库转储包含大量无关历史数据，其中 `diameter` 约有上亿行，并且 ZIP 流校验已发现 CRC 异常。因此禁止直接恢复到当前业务数据库，所有输入均按不可信历史数据处理。

## 目标

1. 从损坏风险可控的暂存流程中提取 11 支钢管的可用数据库记录和文件。
2. 建立旧字段、旧主键与当前数据模型之间可审计、可重复执行的映射。
3. 新增显式的 `BKV` 离线回放数据源，在不连接相机的情况下复用在线检测、缺陷、报警和报表链路。
4. 尝试解析 `.d3img` 三维数据，并转换为当前系统可消费的深度矩阵或点云；无法可靠解析时保留原件和诊断证据，不伪造三维结果。
5. 不改变真实生产模式的八相机、安全门禁、标定和生产资质要求。

## 非目标

- 不恢复所提供数据库中的全部历史记录。
- 不把 BKV 回放伪装成真实相机采集或普通 simulated 数据。
- 不使用 BKV 数据作为真实相机验收或生产算法资质证据。
- 不在 BKV 模式下允许相机连接、标定写入或设备参数修改。

## 输入盘点与保留范围

图片归档包含六个相机目录 `CamImageSource1` 至 `CamImageSource6`，文件类型包括 `.jpg`、`.d3img` 和 `.dat`，钢管序号范围为 `1893700-1893710`。

迁移工具仅处理以下数据：

- `allexcel`：钢管基本信息与缺陷分类汇总；
- `checkrecord`：检测记录；
- `defect`、`defectclass`：缺陷明细及类别映射；
- `diameter`：只能保留可明确关联到目标 11 支钢管且数值有效的测径片段；
- 图片归档：目标序号下六路相机的 2D、3D 和辅助文件。

其他序号、无法关联的数据、损坏行和越界值均不进入当前业务表。

## 总体架构

### 迁移阶段

新增离线迁移工具，以三个归档为输入，生成隔离的 `bkv-data/<batch-id>/` 批次目录。处理分为四步：

1. **清单建立**：记录归档哈希、成员路径、大小、目标序号和完整性状态。
2. **暂存解析**：只读取目标范围，将数据库行和文件元数据写入暂存结构，不接触当前业务表。
3. **校验转换**：完成关联、去重、字段清洗、缺陷类别映射和 `.d3img` 解析。
4. **幂等导入**：校验通过后才写入当前数据库，并保存迁移批次、旧主键、`legacySeqNo` 和来源文件。

重复运行同一批次不得产生重复钢管、检测、缺陷或采集文件记录。当前数据库不得被归档恢复、覆盖或降级。

### 运行阶段

新增显式配置 `captureProvider=bkv`，与真实相机和 `simulated` 模式相互独立：

- 不启动或探测相机采集服务；
- 按 `1893700` 到 `1893710` 的顺序选择回放数据；
- 每次 `capture-once` 消费当前钢管的一组离线文件，生成现有系统可识别的采集和检测结果；
- 回放到第 11 支后进入“已完成”，不自动循环；
- 管理员可显式重置回放位置；
- BKV 健康检查验证数据库、批次清单、文件可读性和回放状态，不声称物理 SDK 或相机在线。

## 数据映射与清洗

- 旧钢管序号映射为稳定的业务标识，并保留 `legacySeqNo`。
- 每个迁移对象保存旧表名、旧主键、批次 ID 和来源成员路径。
- 缺陷类别通过 `defectclass` 映射到当前类型；未知类别写为“待复核”并保留原始名称。
- 无效尺寸、负数、非数值、明显越界值和无法证明关联关系的数据进入隔离报告，不以默认业务值替代。
- `diameter` 只导入目标钢管的有效、可关联片段；若损坏转储无法证明完整性，则标记该钢管测径数据不完整。
- 缺失某一路文件不阻断整支钢管回放，但该相机必须显示“数据缺失”。

## `.d3img` 三维解析

`.d3img` 被视为旧系统三维深度数据，而不是普通附件。解析采用证据驱动的分层策略：

1. 识别文件签名、版本、宽高、像素格式、字节序、头部和数据区边界。
2. 优先检查并使用项目已有或 Capture 6.7 SDK 提供的离线读取能力。
3. 在格式证据充分时，实现有严格边界检查的解析适配器。
4. 将有效深度转换为当前系统统一的深度矩阵或点云产物。
5. 仅在 `.dat` 字段含义可确认时应用标定或采集参数；否则标记为原始相机坐标。

解析必须检查文件长度、尺寸上限、整数溢出、数据区越界、NaN、无效深度比例和异常深度范围。成功结果记录解析器版本和统计摘要；失败结果保留原文件、错误码和诊断信息，不生成伪点云。

## UI 与模式隔离

- 顶部运行状态明确显示“BKV 离线回放”。
- 相机区域显示“离线数据 6/6”或逐路缺失状态，不能显示为真实相机在线。
- 2D 页面读取 `.jpg`；3D/点云页面读取转换后的 `.d3img` 产物。
- 钢管信息、检测时间、缺陷、报警和报表均显示 BKV 来源标记。
- BKV 模式禁用相机连接、相机参数修改和标定设备写入。
- 切回真实生产模式后，继续严格执行八相机、采集存储和 readiness 门禁。

## 完整性与错误处理

- ZIP CRC 异常必须进入迁移报告；不得因解压工具返回部分内容而宣称完整导入。
- 所有目标数据进行行数、序号、主外键、文件存在性和字段范围校验。
- 可恢复数据进入暂存区；损坏、截断、重复冲突或无法关联的数据进入隔离清单。
- 导入采用事务和批次状态；失败不得留下半完成且不可辨认的业务数据。
- 回放时文件丢失、解析失败或记录不完整要返回稳定错误码，并允许跳过单路但不能伪造成功。

## 验收标准

1. 迁移结果只包含 `1893700-1893710` 共 11 个钢管序号。
2. 旧主键、批次和来源可追踪，重复导入不会新增重复记录。
3. 六路文件数量与迁移清单一致，所有缺失和损坏项均可定位。
4. 可解析 `.d3img` 通过宽高、有效点数、深度范围校验，并至少生成一个可视化快照供人工核对。
5. BKV 模式在没有相机服务时可启动并通过自身健康检查。
6. `capture-once` 顺序回放 11 支钢管，结束后停止，重置后从第一支重新开始。
7. 缺陷列表、报警和报表与迁移后的关联记录一致。
8. UI 明确区分 BKV、simulated 和真实生产数据。
9. 切回真实模式后仍严格要求八台相机，BKV 不放宽生产安全策略。
10. 新增迁移、解析、幂等、回放、错误处理和模式隔离测试，且现有测试与构建全部通过。
