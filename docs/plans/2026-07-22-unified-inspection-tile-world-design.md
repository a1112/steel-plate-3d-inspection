# 统一检测图像瓦片世界设计

> **Status: Superseded.** 默认主界面和新媒体接口已由 [检测系统边界与响应式缩略图决策](../design/inspection-boundaries-responsive-thumbnail.md) 取代；本文仅保留为旧瓦片兼容历史。

## 目标

将 BKV 离线文件模式和在线相机模式包装为同一套最小检测图像世界接口。BKV 模式从旧数据库校验快照、JPEG 和 NPZ 获取检测记录、缺陷与图像；在线生产模式从 MySQL 和相机采集存储获取相同语义的数据。前端只渲染统一的可缩放瓦片世界，不再为 BKV 单独展示六张首帧图片。

首版以最小兼容为目标：线扫帧直接连接，不做重叠搜索、配准、融合或巨型原图预生成。

## 参考实现

参考 `G:\Project\SteelDefectDetectionManage` 的虚拟长带与瓦片方案：

- 世界尺寸由单帧尺寸和帧数计算；
- 不预先读取全部图像，也不生成完整马赛克；
- 服务端只读取当前瓦片涉及的原始帧，按需组合并缓存；
- 前端依据视口和缩放等级请求瓦片；
- 缺陷坐标与图像使用同一个世界坐标系。

本项目不直接复制参考工程，而是保留其核心的数据结构和按需渲染方式，并适配六/八相机钢管检测模型。

## 架构

服务端增加统一的 Inspection World 边界：

1. `BkvWorldProvider` 读取经过严格校验的 BKV 运行清单。清单由 `checkrecord.csv`、`defect.csv`、`defectclass.csv`、JPEG、NPZ 和预览产物生成，并保留源文件哈希与隔离证据。
2. `OnlineWorldProvider` 从 MySQL 读取检测记录和缺陷，从相机采集目录或实时采集缓存读取图像帧。
3. 两个 Provider 返回同一套记录、世界元数据、瓦片和缺陷 DTO。
4. 前端使用一个可缩放、可平移的世界画布，不按 Provider 分叉图像渲染逻辑。

统一最小接口包含：

- 检测记录列表及钢管信息；
- 世界元数据：Provider、相机布局、帧尺寸、帧数、方向参数、世界尺寸、瓦片大小和最大等级；
- 世界瓦片：记录、等级、瓦片坐标与图像格式；
- 缺陷：数据库身份、类别、相机、原始帧坐标、世界矩形和可定位状态。

服务运行模式决定 Provider。BKV 模式不连接相机或在线 MySQL；在线生产模式要求 MySQL 可用，不静默回退到 BKV、SQLite 或模拟数据。SQLite 只允许在显式开发或测试配置中使用。

## 世界与方向参数

每支钢管对应一个二维世界。

单相机内部按 `frameNo` 从小到大，将完整线扫帧纵向直接连接。不同相机按配置顺序横向连接。相机宽度允许不同；世界总宽度是各相机变换后宽度之和，世界高度是各相机累计高度的最大值。某相机数据不足时保留空白区域，不移动相邻相机。

首版 BKV 参数为：

```text
cameraOrder: C1, C2, C3, C4, C5, C6
frameOrder: ascending
rotation: 0
flipX: false
flipY: false
```

在线模式使用相同参数模型，当前显式配置 C1-C8。方向变换必须同时作用于瓦片内容和缺陷矩形。后续可以调整每台相机的顺序、帧序、旋转和翻转，而不修改渲染组件。

## 瓦片生成

Level 0 使用原始像素；Level N 相对原始像素缩小 `2^N`。最大等级根据世界宽高和瓦片大小计算，使整管可以低分辨率完整显示。

服务端收到瓦片请求后：

1. 将瓦片世界矩形与相机区域求交；
2. 将相机内矩形与帧累计区间求交；
3. 只读取相交的 JPEG 帧；
4. 按方向参数裁剪、变换并粘贴到当前瓦片；
5. 对高等级瓦片缩放并编码；
6. 使用包含 Provider、记录、布局版本、等级和坐标的键进行有界缓存。

一张瓦片可以跨越帧边界或相机边界。服务端二次产出的是当前请求瓦片，而不是永久的整幅拼接原图。

## BKV 数据与缺陷映射

`checkrecord` 是 BKV 检测记录的权威来源，提供钢管身份、规格、检测时间和声明缺陷数。`defect` 通过 `defect.SeqNo -> checkrecord.SeqNo` 关联记录。`defectclass` 提供类别名称。ID 范围碰巧相同但身份冲突的 `allexcel` 行继续进入 quarantine，不得混入检测记录。

BKV 运行清单需扩充并保留以下缺陷字段：

- `CamNo`、`ImgIndex`；
- `LeftImg2D`、`RightImg2D`、`TopImg2D`、`BottomImg2D`；
- `LeftSteel2D`、`RightSteel2D`、`TopSteel2D`、`BottomSteel2D`；
- 已有类别、等级、置信度、面积和深度字段。

首版使用与原始图片直接对应的帧内坐标定位：

```text
worldX = cameraOffsetX + LeftImg2D
worldY = ImgIndex * frameHeight + TopImg2D
```

矩形宽高来自帧内左右/上下边界。`ImgIndex` 按 BKV 的零基帧号解释。旧整管坐标保留用于追溯和后续标定比较，但不覆盖首版原始帧定位。

方向参数发生变化时，先在相机局部坐标中变换缺陷矩形，再加相机世界偏移。

## 前端交互

BKV 二维页改为一个世界画布：

- 默认按可用区域完整显示整管；
- 支持鼠标滚轮缩放和拖动平移；
- 只请求当前视口及少量邻近瓦片；
- 显示 C1-C6 相机边界和可选帧边界；
- 缺陷框与瓦片同尺度绘制；
- 点击缺陷列表将视口定位到对应相机和帧；
- 保留 JIT 展开和圆柱 3D 作为独立视图。

同一画布组件也作为在线模式的兼容目标。在线 Provider 使用 C1-C8 和 MySQL 数据，但不改变前端世界协议。

## 异常处理

- 缺帧：保留对应世界区域，返回缺失瓦片状态，不用其他帧替补。
- 图片损坏或哈希不符：拒绝相关瓦片并显示读取错误。
- 某相机帧数较少：保持原相机偏移和世界布局。
- 缺陷坐标无效：记录仍显示在列表中，标记为不可定位，不绘制猜测框。
- 方向配置重复、缺失或非法：服务启动失败并指出相机。
- 数据库不可用：在线生产模式明确不可用；BKV 模式不尝试访问在线数据库。
- 文件访问：所有 BKV 路径必须存在于清单白名单并位于批准数据根目录内。

## 测试与验收

1. 坐标单元测试验证帧连接、相机偏移、方向变换和缺陷框映射。
2. 瓦片单元测试使用不同颜色的合成帧验证跨帧、跨相机、缺帧和多级缩放。
3. BKV 清单测试验证数据库字段、零基 `ImgIndex`、源哈希和 quarantine。
4. Provider 契约测试验证 BKV 与在线 MySQL 返回相同 DTO 结构，同时保持数据源隔离。
5. 前端测试验证可见瓦片选择、缩放、平移、缺陷覆盖和缺陷定位。
6. 浏览器冒烟验证 BKV 二维世界、JIT 展开和圆柱 3D；在线冒烟验证 MySQL/八相机边界。

首版完成标准：

- BKV 记录 1893700 的 C1-C6、每路 21 帧形成一个连续世界；
- 数据库缺陷“轧折”定位到 C1 的 `ImgIndex=12` 帧内区域；
- 页面不一次加载 126 张原图，也不生成巨型拼接文件；
- BKV 数据不进入在线 MySQL，在线数据不回退到 BKV；
- BKV 六相机和在线八相机通过同一最小世界协议显示。
