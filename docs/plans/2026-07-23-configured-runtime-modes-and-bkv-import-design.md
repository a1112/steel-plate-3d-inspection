# 配置驱动运行模式与 BKV 标准化导入设计

## 目标

将相机数量、数据来源和可用功能从各子系统的硬编码中移出，由项目配置选择运行模式配置。直连模式使用当前八相机配置；BKV 模式使用独立六相机配置。BKV 旧数据库、JPEG 和 `.d3img` 由独立转换服务写入当前系统标准存储，之后与直连相机数据复用相同的记录、缺陷、文件索引、瓦片和业务界面。

本阶段同时完成：

- 在后台管理中维护运行模式与 BKV 转换配置；
- 配置保存后重启生效；
- 非相机直连模式隐藏采集管理、3D 重建等不适用入口；
- 浏览器中工具页面使用当前页导航，Tauri 桌面端保留独立窗口。

## 现状与问题

当前代码存在多个相互独立的相机数量来源：

- `config/capture/profiles/current-8-time-trigger/profile.json` 已声明八相机直连配置；
- BKV 运行清单生成器、Rust BKV 管理器和部分前端测试写死六相机；
- 采集服务、标定、重建和若干后台界面仍有各自的 6 或 8 默认值；
- BKV 运行时直接读取专用清单，在线运行时读取生产数据库和采集文件索引，数据查询存在两条分支；
- 浏览器工具入口通过 `window.open` 创建弹窗；
- 非直连模式仍展示采集管理和 3D 重建入口。

实际旧 BKV 数据只有 C1-C6：JPEG 和 NPZ 均没有 C7/C8。不得复制或伪造数据补齐八路。

`G:\Project\StraightnessGauge` 的可复用思路是：运行模式配置决定数据根和元数据来源，离线转换产物写入本地目录数据库和标准资源目录，在线与离线通过相同服务接口读取。

## 方案选择

### 方案 A：独立转换服务写入统一标准存储

推荐。BKV 只作为导入源，转换完成后业务服务不再读取旧格式。直连和离线记录共享当前生产记录、缺陷、`capture_file` 索引和文件布局。

优点：

- 数据来源与业务查询彻底解耦；
- 前端、报表、报警、瓦片和后台记录管理只维护一套逻辑；
- 转换可以重试、审计和增量执行；
- 后续接入其他旧系统时只需增加源适配器。

代价是需要独立转换进程、导入账本和一次性旧数据迁移。

### 方案 B：保留 BKV 专用清单，只配置化相机数量

改动较小，但 BKV 与在线数据仍拥有两套查询和文件访问路径，后台与接口会继续积累条件分支，不满足“来源不同、存储内容相同”的目标。

### 方案 C：运行时直接读取旧 BKV 文件

不需要额外转换空间，但旧格式解析、哈希校验和文件扫描进入在线请求路径，性能、恢复性和长期兼容性最差，不采用。

## 配置模型

### 项目入口

新增 `config/project.json`，只负责选择当前运行模式配置，不复制相机参数：

```json
{
  "schema": "steel.project-config.v1",
  "activeRuntimeProfile": "config/runtime-modes/bkv-6.json"
}
```

生产部署可将其切换为 `config/runtime-modes/direct-8.json`。服务启动时解析并规范化路径，配置文件必须位于批准的配置根目录内。

### 运行模式配置

新增两个受版本控制的配置：

- `config/runtime-modes/direct-8.json`
- `config/runtime-modes/bkv-6.json`

公共字段包括：

```json
{
  "schema": "steel.runtime-profile.v1",
  "id": "bkv-6",
  "displayName": "BKV 六相机离线转换",
  "dataSource": "converted-local",
  "cameraConnection": "none",
  "cameraCount": 6,
  "cameras": [],
  "storage": {},
  "capabilities": {
    "directCamera": false,
    "captureManagement": false,
    "reconstruction": false,
    "offlineReplay": true
  }
}
```

`direct-8` 引用现有 `current-8-time-trigger` 采集配置，并声明八路相机。`bkv-6` 明确列出 C1-C6 的旧源目录映射、方向和转换目标，不引用或创建 C7/C8。

相机数组是顺序和身份的权威来源；`cameraCount` 必须等于启用且身份唯一的相机数。服务拒绝空 ID、重复 ID、非连续显示顺序、越界目录和与采集配置不一致的直连配置。

配置保存使用临时文件、刷新和原子替换，并写入现有 `config_revision` 审计。保存只更新待生效配置，响应明确返回 `restartRequired: true`；当前运行进程不热切换数据根、数据库或瓦片坐标。

## BKV 独立转换服务

新增独立的 BKV 导入进程。首版复用现有 Python `.d3img`/NPZ 转换能力，服务自身不提供业务查询。

### 输入

- `database.zip` 解压后的只读 CSV/数据库快照；
- 六路 JPEG 源；
- 六路 `.d3img` 源；
- `bkv-6` 相机映射和允许的源根目录。

源文件始终只读。转换服务记录相对路径、大小、SHA-256、旧记录 ID、相机 ID 和帧号。

### 标准输出

转换目标按当前系统记录组织：

```text
<dataRoot>/
  records/<inspectionId>/
    record.json
    source-provenance.json
    cameras/C1/frames/<sequence>/intensity.jpg
    cameras/C1/frames/<sequence>/depth.npz
    ...
    defects/defects.json
```

本地数据库使用当前服务已有的生产表语义：

- `material_session`
- `production_inspection`
- `capture_file`
- `production_defect`
- 报警和报告所需的现有下游表

BKV 本地数据库允许使用 SQLite，但表结构和业务 DTO 与在线 MySQL 保持一致。在线模式不回退到 BKV SQLite；BKV 模式不访问在线 MySQL。

### 任务账本和发布

转换服务维护独立导入账本，至少记录：

- job ID、源批次和配置版本；
- 状态、进度、当前记录；
- 源哈希、产物哈希；
- 已转换、跳过、隔离和失败数量；
- 错误信息和重试次数；
- 创建、开始、完成时间。

每条记录先写入 `<dataRoot>/imports/.staging/<job>/<record>`，完成结构、哈希、JPEG/NPZ 可读性和六相机覆盖校验后，原子发布到正式记录目录，再在数据库事务中写入记录和文件索引。相同源哈希和配置版本重复执行时必须幂等；失败的暂存目录不得进入业务查询。

旧 BKV 批次 1893700-1893710 通过该服务重新导入。原始 `tmp/legacy-bkv` 保持只读，不在原地改写。

## 运行时数据访问

Rust 服务启动后读取项目配置与运行模式配置，构造统一运行上下文：

- 当前模式、配置 ID 和配置哈希；
- 相机数量与有序拓扑；
- 数据库适配器；
- 标准数据根；
- 功能能力。

BKV 模式从转换后的本地数据库读取记录、缺陷和 `capture_file`，从标准记录目录读取 JPEG/NPZ。在线模式继续从 MySQL 和直连采集存储读取同一模型。

检测世界元数据和相机本地瓦片接口保持统一。瓦片层只看到有序 `capture_file`，不再判断文件是否来自 BKV。`/api/bkv/status` 可保留为兼容标签与导入状态接口，但不再作为记录和瓦片的专用仓库。

新增只读运行配置接口，返回经过净化的信息：

```json
{
  "profileId": "bkv-6",
  "dataSource": "converted-local",
  "cameraCount": 6,
  "capabilities": {}
}
```

不得返回秘密、在线数据库口令或批准根目录之外的内部路径。

## 后台管理

后台“系统配置”增加“运行模式与数据转换”区域：

- 当前项目配置和运行模式；
- 直连/BKV 模式说明；
- BKV 六相机有序映射；
- 旧数据库、JPEG、`.d3img` 源根；
- 标准存储根和本地数据库位置；
- 配置校验结果；
- 保存并提示重启生效；
- 最近转换任务、进度、成功/跳过/隔离/失败数量；
- 启动转换、重试失败项和查看错误详情。

写配置和触发转换继续要求 `admin.config` 或更细的新增管理权限，并写审计日志。普通操作员只能读取运行模式摘要。

## 功能能力与界面

页面不能从 `provider` 名称猜测功能，而是读取后端返回的能力：

- `directCamera`
- `captureManagement`
- `reconstruction`
- `offlineReplay`

当 `directCamera=false`：

- 页脚不渲染“采集管理”和“3D 重建”入口；
- 系统状态/配置中心中不渲染相同入口；
- 直接访问 `?app=capture` 或 `?app=bar-surface` 时返回主检测界面并提示当前模式不可用；
- Rust 硬件、标定写入和直连重建操作继续在服务端拒绝，不能只依赖前端隐藏。

后台管理始终保留，因为它承载 BKV 配置和转换状态。

检测主视图的 2D、历史 NPZ 观察和缺陷分析不等同于“3D 重建工作台”，在 BKV 模式仍可根据标准产物展示。

## 浏览器与 Tauri 导航

`app-windows` 保留一个统一入口：

- Tauri 环境继续创建或聚焦独立 `WebviewWindow`；
- 浏览器环境使用 `window.location.assign('/?app=parameters')` 等当前页导航；
- 浏览器跳转进入历史栈，可使用返回按钮回到主界面；
- 统一使用查询参数路由，保留对旧 hash 地址的兼容解析。

所有入口在导航前检查运行能力。浏览器深链接仍由目标页面进行第二次能力校验。

## 错误处理

- 项目或模式配置无效：服务启动失败并指出稳定错误码，不静默回退到其他模式。
- 配置与相机数组不一致：拒绝保存。
- BKV 源缺失：转换任务失败，现有已发布记录继续可读。
- 单条记录损坏：进入隔离清单，不污染数据库或正式目录。
- 转换服务不可用：主业务服务继续读取已发布数据，后台显示转换服务不可用。
- 未授权配置或转换操作：返回 401/403 并审计。
- 非直连模式访问硬件接口：返回稳定的能力不可用错误。

## 测试与验收

### 配置

- 解析 `direct-8` 和 `bkv-6`；
- 拒绝数量不一致、重复相机、路径越界和非法能力组合；
- 保存配置产生版本记录并返回重启要求；
- 启动不接受无效配置或隐式模式回退。

### 转换服务

- 六相机旧数据生成标准记录目录、JPEG、NPZ 和数据库索引；
- 源文件保持不变；
- 重复执行幂等；
- 中断后可恢复；
- 缺帧、哈希错误、未知相机和数据库关联错误进入隔离；
- 未完成暂存记录不可查询。

### 服务端

- BKV SQLite 与在线 MySQL 返回相同记录、缺陷和检测世界 DTO；
- BKV 不读取 MySQL，在线不读取 BKV 根；
- 相机数量来自运行配置；
- 非直连模式拒绝硬件和重建管理接口。

### 前端

- BKV 显示 C1-C6，不显示 C7/C8；
- 直连八相机显示 C1-C8；
- 后台可读取、校验和保存 BKV 配置并显示重启提示；
- 后台显示转换任务状态；
- 非直连模式不渲染采集管理和 3D 重建入口；
- 浏览器入口使用当前页导航，Tauri 仍使用窗口。

### 浏览器验证

- BKV 模式页脚仅保留后台管理和适用工具；
- 后台管理可查看六相机配置和转换状态；
- 浏览器后台管理入口在同一标签页跳转，返回可恢复主界面；
- 旧批次 1893700-1893710 从标准存储加载记录、缺陷和瓦片；
- 直连模式配置仍声明八相机且不访问 BKV 本地数据库。
