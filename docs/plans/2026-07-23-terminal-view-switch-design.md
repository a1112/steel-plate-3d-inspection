# 终端在线检测与 BKV 回放切换设计

## 背景

当前终端在 `/api/bkv/status` 返回 `provider=bkv` 且 `ready=true` 时直接渲染 BKV 离线回放页面。该自动分支没有保留原在线检测主界面的入口，用户也无法通过刷新或修改普通导航返回在线界面。

## 方案比较

1. 仅使用 React 内存状态：实现最少，但刷新后会再次自动进入 BKV。
2. 使用 `localStorage`：可长期记忆选择，但模式状态被隐藏在单机存储中，不利于排查和分享链接。
3. 使用 URL 查询参数：以 `view=online|bkv` 明确当前终端视图，刷新后保持，链接可观察、可复制，且不改变后端数据源。

采用方案 3。未提供 `view` 时继续沿用当前自动探测行为，保持现有启动兼容性。

## 交互设计

页脚“更多”菜单包含两个条目：

- `在线检测`：始终可用；显示原钢管 3D 表面检测主界面。
- `离线回放`：仅当 BKV 服务明确报告就绪时可用；显示 BKV 六相机离线回放。

当前显示的条目使用选中样式并设置 `aria-current="page"`。点击另一条目时更新 URL 查询参数与 React 状态，不整页刷新。BKV 不可用时保留“离线回放”条目和“仅 BKV 模式可用”说明。

## 状态与数据流

`App` 读取 URL 中的 `view` 并维护终端视图状态：

- `view=online` 强制显示在线主界面，即使 BKV 服务就绪。
- `view=bkv` 仅在 BKV 服务就绪时显示离线回放。
- 未指定时使用 `auto`：BKV 就绪则显示回放，否则显示在线主界面。

`App` 将两个菜单项的 `available`、`active` 和回调传给共享 `AppFooter`。在线界面仍读取现有检测快照；BKV 界面仍使用现有 BKV 数据与瓦片接口，模式切换不改变数据库或相机控制逻辑。

## 异常处理

若 URL 指定 `view=bkv` 但服务不可用，界面回退到在线主界面，离线条目禁用。所有 URL 更新保留已有的 `app` 和其他查询参数。

## 测试

- `AppFooter`：验证双入口、当前态、禁用态和回调。
- `App`：验证 BKV 自动进入、切到在线界面后不会被自动切回、再切回 BKV。
- 浏览器烟测：验证真实 `5174` 页脚菜单可以在两个界面间往返，并保留原有瓦片滚动与缩放检查。
