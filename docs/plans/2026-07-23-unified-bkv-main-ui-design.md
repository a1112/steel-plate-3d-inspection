# 相机 / BKV 统一主界面设计

日期：2026-07-23

## 背景与根因

当前服务以 `provider=bkv` 启动时，`/api/health/details` 已明确：

- 检测服务正常；
- BKV 六路离线数据可用；
- 相机 SDK 与触发网关不属于 BKV 就绪条件；
- 触发网关是可选依赖。

但客户端仍存在两套互相绕开的界面：

- 在线模式渲染完整 `InspectionDashboard`，继续读取空的生产 SQLite 快照；
- BKV 模式直接返回独立的 `BkvCompatibilityApp`；
- 在线 `BrandHeader` 无条件计算相机、报级器、编码器、PLC、L2 和触发网关状态；
- 即使触发网关在 BKV 模式下是可选依赖，客户端仍将其计入“服务异常”。

结果是当前 BKV 环境的主界面没有旧检测记录和图像，同时顶部会显示与实际模式无关的硬件异常。

## 目标

1. 主程序始终使用统一的品牌头、主工作区和页脚。
2. 由明确的终端数据模式控制页面内容：
   - `online`：在线相机与生产数据库；
   - `bkv`：六路离线 BKV 数据。
3. BKV 模式顶部不显示任何在线硬件状态，改为显示：
   - `BKV 模式`；
   - 六路离线数据覆盖；
   - 当前批次；
   - 检测数据服务状态。
4. BKV 模式不把相机、SDK、PLC、L2、编码器或可选触发网关计为服务异常。
5. 将独立离线回放页的检测记录与二维检测图像世界迁入主界面。
6. 相机模式保持现有 8 路相机、硬件状态、数据库记录和实时跟随逻辑。
7. 显式选择在线模式但当前 provider 为 BKV 时，显示模式不匹配提示，不伪造相机在线状态。

## 方案选择

### 采用：客户端数据适配 + 统一主界面

增加纯函数 BKV 适配层，将 `BkvMaterial[]` 转成现有 `InspectionSnapshot`：

- 每个旧材料成为一条 `InspectionRecord`；
- 每个旧材料成为一个 `PlateInspection`；
- `inspectionId` 使用旧序号，供现有 inspection-world API 加载瓦片；
- 旧缺陷转换成主界面可筛选、可选择的 `DefectItem`；
- `source` 明确标记为 `bkv`，禁止演示图像回退；
- 设备状态保持离线但不进入 BKV 头部计算。

这样可以直接复用：

- `LeftSidebar` 检测记录；
- `PlateMap` 与 `InspectionWorldCanvas`；
- 缺陷过滤和缺陷列表；
- 主界面选中记录状态；
- 已实现的按视口加载、滚动与缩放逻辑。

### 未采用：继续维护独立 BKV 页面

改动最小，但仍有两套布局和状态模型，无法满足“主界面根据当前模式显示不同内容”和记录/主图迁移要求。

### 未采用：由 Rust 直接改写 `/api/inspection/snapshot`

长期可将 provider 适配放在服务端，但当前需要在 Rust 中复制大量前端领域字段映射，并改变公共快照协议。该方案扩大了数据库与在线模式回归范围，不适合作为本次最小兼容边界。

## 架构

### 模式解析

`App` 继续支持 `?view=online|bkv`：

- BKV provider 可用且未显式选择 online：进入 BKV；
- 显式 `view=bkv`：进入 BKV，若 provider 不可用则显示 BKV 数据错误；
- 显式 `view=online`：进入在线主界面；
- 非 BKV provider：默认在线模式。

模式是主界面的一级输入，不再通过“是否直接返回另一棵组件树”表达。

### 数据加载

在线模式：

1. 读取 `/api/inspection/snapshot`；
2. 保持 8 秒实时刷新；
3. 读取相机、触发、网络与三服务状态；
4. 使用生产记录的 inspection-world 或采集图像。

BKV 模式：

1. 读取 `/api/bkv/status`；
2. 读取 `/api/bkv/materials`；
3. 调用纯适配函数生成 `InspectionSnapshot`；
4. 默认选择第一条旧记录；
5. 选择记录时，以旧序号调用现有：
   - `/api/inspection-world/meta`；
   - `/api/inspection-world/defects`；
   - `/api/inspection-world/tile`。

BKV 不启动在线快照、相机状态、触发网关和网络轮询。

### 顶部状态分化

`BrandHeader` 接收判别联合类型 `runtimeMode`。

在线分支保留：

- 触发状态；
- 报级器网口；
- 相机状态；
- 编码器、PLC、L2；
- 检测、采集、触发三服务；
- 运行/异常汇总。

BKV 分支只显示：

- `BKV 模式 / 离线回放`；
- `离线数据 6/6`；
- 批次号；
- 检测数据服务状态；
- 正常时“数据就绪”，错误时明确的 BKV 数据错误。

通知中心、窗口控制和在线分析折叠按钮继续按页面上下文保留。

### 主工作区

BKV 复用在线主布局，但内容按模式调整：

- 左侧材料卡显示“来源：旧 BKV 文件”和硬件禁用提示；
- 记录列表使用主界面 `LeftSidebar` 的检测记录表；
- 中部默认显示二维 `InspectionWorldCanvas`，相机为 C1-C6；
- 顶部跟随状态替换为“BKV 离线记录 / 当前旧序号 / 批次”；
- 不显示“每 8 秒实时跟随最新检测”；
- 右侧缺陷过滤与列表读取适配后的 BKV 缺陷；
- 下部分析区可以显示旧缺陷基本信息；没有标准剖面数据时保持明确空态。

本次迁移的主图是二维检测图像世界。旧 JIT 展开与圆柱预览保留为兼容组件代码，但不再作为独立 BKV 首页；后续可在统一主图的视图菜单中继续接入。

## 错误处理

- BKV 状态存在但材料读取失败：保留统一主壳，显示“BKV 数据读取失败”和重试入口。
- BKV 状态不可用且显式选择 BKV：显示模式不可用，不回退为在线数据。
- 在线模式遇到 BKV provider：显示“当前采集源为 BKV，在线相机模式不可用”，硬件状态不伪造为在线。
- 单个 inspection-world 瓦片失败：沿用现有五秒重试与局部失败提示，不清空整幅图。
- BKV 可选触发网关不可达：不计入 BKV 服务异常。

## 测试策略

### 单元测试

- BKV 材料适配为 11 条记录、11 个检查和六相机 inspection id。
- 缺陷映射保留旧缺陷 ID、相机、类别、置信度与位置。
- BKV `BrandHeader` 显示模式、批次、6/6 数据，不出现相机/PLC/触发/服务异常。
- 在线 `BrandHeader` 继续显示全部硬件状态。

### 集成测试

- ready BKV provider 进入统一 `InspectionDashboard`，不再出现独立“BKV 离线回放”页面。
- BKV 左侧出现旧检测记录，选中记录后主图 record id 更新。
- BKV 不调用在线快照、相机和触发状态接口。
- 显式 online 仍读取在线快照并保留在线状态栏。
- 页脚在线/BKV 切换仍更新 URL 与当前模式。

### 运行时验收

在当前 4874 BKV 服务上验证：

- 顶部显示 `BKV 模式` 和 `6/6 离线数据`；
- 顶部没有“相机状态”和“服务异常”；
- 左侧显示 11 条旧检测记录；
- 主图显示 C1-C6 瓦片；
- 选择 1893703 后主图与缺陷切换；
- 切到 online 时显示明确的 BKV provider 模式不匹配；
- 生产构建和全量前端测试通过。
