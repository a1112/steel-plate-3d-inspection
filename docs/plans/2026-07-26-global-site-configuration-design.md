# 全局现场配置与后台管理布局设计

## 背景

后台管理的“配置”页目前同时承载运行模式、相机、检测规则、配置版本、连接 JSON 和采集 JSON。页面在常见桌面分辨率下形成高度不一致的多列卡片和超长编辑区，模块关系不清晰。现场配置切换仍依赖手工修改 `config/project.json`，而运行模式配置只能原地编辑，不能安全地新建、复制和切换。

不同现场可能使用完全不同的数据来源与硬件能力。运行模式会决定相机、采集、转换、存储和 3D 重建等后续配置是否存在，因此必须在创建现场配置时确定，并在创建后保持只读。

## 目标

- 新增“全局配置”后台分区，集中管理现场配置的新建、复制、检查、切换和删除。
- 把每个现场表示成一个自包含的配置包，并由项目配置指向当前生效包。
- 创建现场配置时设置运行模式，创建后禁止修改模式。
- 切换配置后明确进入“等待重启生效”状态；服务重启并成功加载后才视为生效。
- 在“总览”显示当前现场、运行模式、数据来源、相机数量、配置状态和可用性检查结果。
- 按运行模式动态显示后台配置模块，BKV 模式不显示相机直连、采集管理和 3D 重建配置。
- 重排现有“配置”页面，消除多个大型表单和 JSON 编辑器挤在同一栅格的问题。

## 非目标

- 不在配置切换时热重载生产服务。
- 不在默认检查中启动采集、改变设备状态或写入生产数据库。
- 不实现跨机器的集中配置分发平台。
- 不把所有配置迁移到数据库。

## 方案选择

采用“现场配置包”方案。每个现场使用独立目录保存清单和模式相关配置，`config/project.json` 只保存当前配置指针和待重启状态。

相比单个大型 JSON，该方案便于版本对比、复制、备份和按模式拆分；相比数据库方案，它保留当前文件配置的启动独立性，避免服务启动依赖数据库。

## 配置模型

现场配置目录：

```text
config/
  project.json
  sites/
    bkv-default/
      site.json
      runtime.json
      connection.json
      capture.json
    direct-production/
      site.json
      runtime.json
      connection.json
      capture.json
```

`site.json` 是现场配置清单，至少包含：

```json
{
  "schema": "steel.site-config.v1",
  "id": "bkv-default",
  "displayName": "BKV 六相机现场",
  "mode": "bkv",
  "runtimeProfile": "runtime.json",
  "connectionConfig": "connection.json",
  "captureConfig": "capture.json"
}
```

`mode` 在创建后不可修改。服务端更新接口不接受对既有配置 `mode` 的修改，前端详情页也只读显示该字段。

`project.json` 扩展为：

```json
{
  "schema": "steel.project-config.v1",
  "activeSiteConfig": "config/sites/bkv-default/site.json",
  "pendingRestart": false
}
```

配置切换只原子更新 `activeSiteConfig` 并设置 `pendingRestart: true`。当前进程继续使用启动时加载的配置，直到服务重启。

## 后台信息架构

后台导航调整为：

- 总览
- 服务
- 数据
- 全局配置
- 配置
- 规则
- 账号
- 权限
- 审计
- 安全

“全局配置”沿用 `admin.config` 权限，避免引入不必要的新权限迁移。“配置”保留当前模式允许的模块配置，不再承担现场配置的新建和切换。

### 全局配置页面

页面采用固定工具栏加主从布局：

- 顶部状态栏：当前运行配置、目标配置、是否等待重启、最近检查时间。
- 左侧配置列表：名称、模式、相机数、可用性状态、当前/待生效标记。
- 右侧配置详情：基础信息、模式摘要、依赖配置、检查结果和操作区。
- 操作：新建、复制、重命名、删除、默认检查、深度检查、切换。

新建流程：

1. 输入名称与唯一 ID。
2. 选择运行模式。
3. 根据模式创建最小配置模板。
4. 运行默认检查。
5. 保存配置包。

模式只在第 2 步可选。复制配置会继承原配置模式。

切换流程：

1. 对目标配置执行默认检查。
2. 检查失败时禁止切换，并展示阻断项。
3. 检查通过后确认切换。
4. 原子写入项目配置并标记等待重启。
5. 总览和全局配置页持续显示“等待重启生效”。

当前配置和待生效配置均不可删除。

### 总览

总览新增“当前现场配置”卡片和“配置可用性”卡片：

- 现场名称与配置 ID
- 启动时生效配置与待生效配置
- 运行模式、数据来源、相机数量
- 配置根目录与配置哈希
- 正常、警告、错误检查数量
- 最近检查时间
- 等待重启提示
- 运行默认检查和进入全局配置的入口

总览只自动执行非侵入式默认检查，不执行深度设备探测。

## 模式驱动的后台能力

运行模式决定后台配置分区中的模块：

### 相机直连模式

- 相机配置
- 采集与触发
- PLC/编码器
- 存储
- 算法
- 3D 重建

### BKV 模式

- 转换服务
- 旧数据库或 MySQL 数据源
- 原始图像目录
- 标准存储目录
- 字段映射
- 六相机映射
- 算法

BKV 模式隐藏相机直连、采集管理和 3D 重建模块。模块可见性由服务端返回的模式与能力字段驱动，前端不自行推断。

## 可用性检查

检查结果统一使用：

```json
{
  "id": "storage.convertedRoot",
  "label": "标准数据目录",
  "status": "normal",
  "message": "目录可写",
  "blocking": false
}
```

状态为 `normal`、`warning` 或 `error`。存在 `blocking: true` 的错误时禁止切换。

### 默认检查

- Schema、必填字段和 ID 合法性
- 模式相关配置是否完整
- 所有引用文件是否位于允许的配置根目录内
- 文件和目录存在性、读写权限
- 数据库和 HTTP 服务连通性
- 相机数量、编号、顺序和映射一致性
- 输出目录剩余空间
- 能力字段与运行模式一致性

默认检查只做读取、连接和权限探测，不启动采集、不改变设备状态、不写生产数据。

### 深度检查

- 相机直连模式：探测驱动和设备是否可发现，但不开始采集。
- BKV 模式：检查转换服务、数据源查询和样本文件可读性，但不触发转换和导入。

深度检查只能手动触发。

## 服务端接口

新增管理接口：

- `GET /api/admin/site-configs`
- `GET /api/admin/site-configs/:id`
- `POST /api/admin/site-configs`
- `POST /api/admin/site-configs/:id/clone`
- `PATCH /api/admin/site-configs/:id`
- `DELETE /api/admin/site-configs/:id`
- `POST /api/admin/site-configs/:id/check`
- `POST /api/admin/site-configs/:id/activate`

所有接口使用 `admin.config` 权限并写入审计日志。路径必须经过规范化并验证仍位于 `config/sites` 根目录下。

原有 `/api/admin/runtime-profile` 保留兼容读取能力，但后台页面改用现场配置接口。旧配置在启动时自动映射为一个只读兼容现场配置，随后可通过复制生成正式现场配置包。

## 配置加载与回退

启动时：

1. 读取 `project.json`。
2. 解析并校验 `activeSiteConfig`。
3. 加载现场清单和模式相关配置。
4. 生成运行配置和能力集合。
5. 成功后清除 `pendingRestart` 并记录当前配置哈希。

若新配置加载失败，服务返回明确的启动错误，不覆盖上一份已验证配置。激活操作在修改项目指针前保存上一指针，供管理员恢复。

当前出现的 `runtime profile must be a file beneath the allowed root` 需要通过统一的配置根路径解析修复：相对路径以项目配置所在的配置根目录为基准，规范化后再执行包含性检查。

## 页面布局

- 后台主体使用“固定头部和导航 + 单内容滚动区”。
- 全局配置页使用 `minmax(240px, 320px) minmax(0, 1fr)` 主从栅格。
- 现有配置页改为左侧模块导航和右侧单模块编辑区。
- 相机表单、配置版本、连接 JSON 和采集 JSON 不再同时占据页面。
- JSON 编辑器获得稳定最小高度，并仅在对应模块中渲染。
- 窄屏下主从栅格折叠为上下布局，操作栏允许换行。
- 页面切换时保留当前模块，但不保留未保存草稿。

## 测试策略

### Rust

- 现场配置创建、复制、列举和删除。
- 模式字段创建后不可修改。
- 路径越界、符号链接越界和非法 ID 被拒绝。
- 默认检查按模式产生正确检查项。
- 阻断错误禁止激活。
- 激活原子更新项目配置并设置等待重启。
- 当前配置和待生效配置不能删除。
- 旧项目配置可以映射为兼容现场配置。

### React

- 新增“全局配置”导航和权限控制。
- 新建时可选择模式，编辑时模式只读。
- 不同模式显示不同配置模块。
- 检查结果、阻断状态和等待重启状态正确显示。
- 总览显示当前现场与配置检查摘要。
- 配置页使用单模块布局，不同时渲染两个大型 JSON 编辑器。

### 浏览器验收

- 在 1787×1272、1366×768 和窄窗口下检查后台布局。
- 创建 BKV 六相机配置并验证只出现 BKV 相关模块。
- 创建直连八相机配置并验证相机、采集和重建模块。
- 切换配置后确认主界面仍使用当前配置，后台显示等待重启。
- 重启后确认新配置生效且等待状态清除。
