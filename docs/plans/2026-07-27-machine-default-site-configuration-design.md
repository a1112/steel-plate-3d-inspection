# 当前电脑默认现场配置与隔离配置包设计

## 背景

系统已经使用 `config/project.json` 指向 `config/sites/<site-id>/site.json`，
并在后台管理的“全局配置”页面管理现场配置。现有选择仍属于仓库级状态：
不同电脑共用同一个项目配置时，无法独立指定本机默认现场；切换配置会修改仓库文件，
也无法区分环境变量覆盖、当前电脑默认和仓库回退。

现场配置还可能引用配置目录之外的算法或映射文件。这样不利于完整复制、导入、
导出和审查，也可能让一个现场意外使用另一个现场的配置。

当前开发电脑名为 `LCX_ACE`，其典型运行方式接近六相机 BKV 离线模式。

## 目标

- 当前电脑的默认现场配置只保存在当前电脑，不提交到仓库。
- 环境变量可以临时、显式覆盖当前电脑默认配置。
- 未设置本机默认时，继续使用仓库中的 `config/project.json` 作为回退。
- 全局配置右侧显示仓库默认、当前电脑默认、当前运行、选择来源和重启状态。
- 用户可以在全局配置右侧把一个配置设为当前电脑默认或清除本机默认。
- 新建现场时按配置 ID 创建完整、自包含的配置目录。
- 配置的复制、导入和导出以整个目录为边界。
- 现场配置包含其运行所需的非秘密和明文连接凭据，并允许提交到内部仓库。
- 模式仍只在新建时设置，后续不可修改。

## 非目标

- 不实现跨电脑的集中配置分发或注册中心。
- 不在运行中热切换现场配置。
- 不根据电脑名自动猜测并切换未知配置。
- 不把当前电脑默认配置写入用户配置目录或仓库文件。
- 不静默回退无效的环境变量或注册表选择。

## 方案选择

采用“环境变量覆盖 + Windows 机器注册表默认 + 仓库回退”的混合选择器。

### 选择优先级

```text
STEEL_SITE_CONFIG_ID
  > HKLM 当前电脑默认配置 ID
  > config/project.json 仓库默认配置
```

环境变量适合安装、测试、维护和一次性覆盖；HKLM 是机器范围状态，适合服务账户和
同一电脑上的所有用户；仓库配置保证未部署本机状态时仍有确定的默认值。

不采用仅注册表方案，因为它削弱命令行和非 Windows 开发能力。不采用
“电脑名到配置 ID 的仓库映射”，因为它会把部署状态混入产品配置并产生提交冲突。

## 电脑身份与注册表

Windows 注册表位置：

```text
HKLM\SOFTWARE\SteelInspectionRuntime\Configuration
  DefaultSiteConfigId = REG_SZ
```

安装器创建该键，并授予运行服务账户读取和写入该值的权限。普通开发进程没有写权限时，
服务仍可读取；管理页面明确显示“注册表不可写”，设置操作返回可诊断错误，不退化到
`HKCU`。

电脑名优先通过 Windows 系统 API 读取，开发环境可以使用操作系统主机名回退。
电脑名仅用于显示、默认名称建议和审计，不直接决定配置：

```text
LCX_ACE · BKV 离线
```

## 启动选择与失败策略

服务启动时：

1. 确定项目配置根目录，继续支持 `STEEL_PROJECT_CONFIG_PATH`。
2. 读取 `STEEL_SITE_CONFIG_ID`。若存在，按配置 ID 解析现场目录。
3. 环境变量不存在时读取 HKLM 的 `DefaultSiteConfigId`。
4. 注册表值不存在时读取 `config/project.json` 的 `activeSiteConfig`。
5. 校验选择到的配置包及其全部引用。
6. 加载运行配置并记录选择来源。

显式选择必须失败关闭：

- 环境变量指定无效 ID、缺失目录或损坏配置时，服务拒绝启动。
- 注册表指定无效 ID、缺失目录或损坏配置时，服务拒绝启动。
- 只有注册表值不存在时才使用仓库回退。
- 不因读取错误或校验错误自动加载另一个现场。

这能避免机组在配置损坏时悄悄使用不匹配的相机、数据库或算法参数。

## 运行状态模型

服务公开以下状态：

- `machineName`：当前电脑名。
- `environmentSiteId`：环境变量覆盖 ID，没有时为空。
- `machineDefaultSiteId`：注册表默认 ID，没有时为空。
- `repositoryDefaultSiteId`：`project.json` 的仓库回退 ID。
- `effectiveStartupSiteId`：按优先级计算的下一次启动目标。
- `runningSiteId`：当前进程实际加载的 ID。
- `selectionSource`：`environment`、`registry` 或 `repository`。
- `restartRequired`：`effectiveStartupSiteId != runningSiteId`。
- `machineDefaultWritable`：当前服务是否能写入机器注册表。
- `machineDefaultError`：注册表不可读或不可写时的诊断信息。

重启状态由目标 ID 与运行 ID 比较得出，不为本机选择额外保存
`pendingRestart` 布尔值。仓库配置原有的 `pendingRestart` 保留用于兼容已有配置切换，
但全局配置界面的“设为当前电脑默认”不修改 `project.json`。

环境变量覆盖存在时，本机默认仍可读取和显示，但设置、清除按钮禁用并提示
“当前由环境变量管理”，避免用户以为注册表修改会在下次启动生效。

## 自包含现场配置包

每个配置 ID 对应一个独立目录：

```text
config/sites/bkv-offline-lcx-ace/
  site.json
  runtime.json
  connection.json
  capture.json
  algorithm.json
  mapping.json
```

### 文件职责

- `site.json`：配置 ID、显示名称、不可变模式和文件清单。
- `runtime.json`：数据来源、相机数量、运行能力和各子配置的相对引用。
- `connection.json`：数据库、网络共享、目录和明文连接凭据。
- `capture.json`：相机直连采集参数；BKV 模式生成显式禁用模板。
- `algorithm.json`：算法、输出、保留和处理参数。
- `mapping.json`：相机顺序、源相机、字段和缺陷映射。

所有引用必须是相对于当前配置目录的普通相对路径。禁止：

- 绝对路径形式的配置引用；
- `..` 路径跳出；
- 符号链接或重解析点跳出；
- 引用 `config/algorithm`、`config/runtime-modes` 或另一个现场目录。

数据目录、数据库地址或网络共享自身可以使用部署所需的绝对地址；隔离规则约束的是
“配置文件引用”，不是生产数据位置。

### 新建和复制

新建现场时：

1. 用户输入显示名称和配置 ID。
2. 用户选择 BKV 或相机直连模式。
3. 服务按模式生成完整目录和全部标准文件。
4. BKV 模式默认名称建议为 `BKV 离线 - <电脑名>`，ID 建议为
   `bkv-offline-<规范化电脑名>`。
5. 创建后执行默认可用性检查。

显示名称后续可以在右侧修改，模式不可修改。复制操作复制整个目录、重写配置 ID 和
显示名称，并重新检查所有内部引用。

## 明文凭据

本系统按内部安全使用要求，将现场连接密码保存在 `connection.json`，随配置目录提交、
复制、导入和导出。界面和审计必须明确标记配置包包含连接凭据。

API 日志和普通界面摘要不得回显密码值；只有具有 `admin.config` 权限的配置编辑器可以
读取和修改完整文件。审计记录操作人、配置 ID、操作类型和结果，不记录密码内容。

## 导入与导出

### 导出

- 导出整个 `config/sites/<id>` 目录为 ZIP。
- ZIP 顶层只包含一个与配置 ID 相同的目录。
- 导出前执行默认检查。
- 确认对话框显示“包含明文连接凭据”。
- 记录 `site-config.export` 审计事件。

### 导入

1. 把 ZIP 解压到配置根目录下的临时目录。
2. 拒绝绝对路径、`..`、重复路径、符号链接和重解析点。
3. 验证顶层目录、`site.json` ID、目录 ID 和文件清单一致。
4. 校验模式、配置文件 schema、内部引用和凭据文件存在。
5. 拒绝覆盖现有配置 ID；重命名应使用导入后的复制/重命名流程。
6. 校验通过后原子移动到 `config/sites/<id>`。
7. 记录 `site-config.import` 审计事件。

导入失败时删除临时目录，不留下半导入配置。

## 后台管理界面

“全局配置”右侧详情增加：

- 可编辑显示名称；
- 当前电脑名；
- 仓库默认标记；
- 当前电脑默认标记；
- 当前运行标记；
- 环境变量覆盖标记；
- 下一次启动配置和选择来源；
- 等待重启提示；
- “设为当前电脑默认”；
- “清除本机默认”；
- “导入配置”和“导出配置”。

配置列表同步显示“仓库默认 / 本机默认 / 当前运行 / 待重启”徽标。

设置默认流程：

1. 检查 `admin.config` 权限。
2. 对目标配置执行默认可用性检查。
3. 阻断错误存在时拒绝设置。
4. 写入 HKLM 注册表。
5. 重新读取并确认写入值。
6. 返回更新后的机器选择状态。
7. 页面显示“重启后生效”。

清除流程执行同样的权限、审计和写后确认，并显示即将使用的仓库回退配置。

## API

新增管理接口：

- `GET /api/admin/site-configs/machine-default`
- `PUT /api/admin/site-configs/machine-default`
- `DELETE /api/admin/site-configs/machine-default`
- `POST /api/admin/site-configs/import`
- `GET /api/admin/site-configs/export?id=<id>`

机器默认接口沿用 `admin.config` 权限。导入和导出请求受大小、路径、文件数量和超时限制。
导出响应使用附件下载，不把 ZIP 内容包装进 JSON。

现有现场配置列表和详情响应增加机器选择状态，不由前端自行推断。

## 测试

### Rust 单元测试

- 环境变量高于注册表和仓库回退。
- 注册表高于仓库回退。
- 注册表值不存在时使用仓库回退。
- 环境变量或注册表的无效 ID 阻止启动。
- 选择来源和重启状态计算正确。
- 注册表不可读、不可写时返回稳定错误。
- 新建 BKV 和直连配置生成完整自包含目录。
- 配置引用不能跳出本目录或引用其它现场。
- 复制后所有引用仍指向新目录内部。
- 导入拒绝路径穿越、链接、重复文件、ID 不一致和覆盖。
- 导出包含完整配置和连接凭据，但审计不包含密码值。

Windows 注册表实现使用可替换的存储接口。常规测试使用内存实现，不写真实注册表。

### 前端测试

- 右侧显示电脑名和三种默认/运行状态。
- 环境变量覆盖时设置按钮禁用。
- 设置或清除成功后显示重启提示。
- 注册表不可写时显示明确错误。
- 新建默认名称和 ID 包含规范化电脑名。
- 导入/导出凭据警告和操作状态正确。

### 目标机与浏览器验收

- Windows 验收脚本在受控临时注册表键验证读写和 ACL，不修改正式默认值。
- 重启服务前后验证 `restartRequired` 从 `true` 变为 `false`。
- 验证无环境变量、注册表默认和环境变量覆盖三种启动路径。
- 浏览器验证常用桌面分辨率下的徽标、按钮、提示和滚动布局。

## 迁移

现有 `config/sites/bkv-default` 迁移为完整自包含目录，把外部算法引用复制为本目录内的
`algorithm.json`，并新增 `mapping.json`。`config/project.json` 继续把它作为仓库回退。

首次部署没有注册表值时行为不变。管理员可在全局配置右侧选择
`bkv-default` 或新建的 `bkv-offline-<电脑名>`，设为当前电脑默认后重启服务。

旧 `config/runtime-modes` 继续保留为迁移输入，但不能成为新现场包的运行时引用。
